# Удаление обновлятора приложения

Удалены реализации:

- app/exteraless/updater/GitHubUpdater.java, UpdaterSheet.java, UpdateSheet.java;
- tw/nekomimi/nekogram/helpers/remote/UpdateHelper.java;
- org/telegram/ui/Components/BlockingUpdateView.java, UpdateAppAlertDialog.java, UpdateLayout.java.

Пути выше указаны относительно TMessagesProj/src/main/java.
GitHub Releases больше не опрашиваются обновлятором. Удалён второй механизм получения
обновлений из Telegram-канала и обновление file reference для его APK.
Из настроек и меню профиля убраны проверка обновлений и выбор канала; логотип в
настройках больше не открывает updater sheet. Убрана автоматическая проверка при resume.

Старые appUpdate/appUpdateBuild/appUpdateCheckTime удаляются из настроек при загрузке
и сохранении SharedConfig. Старые метаданные больше не десериализуются. Существующие
скачанные APK из прежних версий автоматически не удаляются; при необходимости их
можно удалить через очистку кэша. Новый код их не использует.

Оставлены нейтральные методы совместимости SharedConfig/ApplicationLoader/LaunchActivity
и пустой IUpdateLayout для вызывающего UI-кода. Они не проверяют, не скачивают и не
устанавливают обновления. Старые ссылки tg://update и кнопки обновления для неподдерживаемого
контента показывают сообщение о ручной установке вне приложения. TL-схема обновлений
в TLRPC оставлена как часть сгенерированного протокола. Старый AutoUpdateChannel
оставлен для совместимости с плагинами, его значение больше не включает обновлятор.

В манифесте REQUEST_INSTALL_PACKAGES помечено tools:node="remove", чтобы разрешение
не вернулось из manifest зависимости. Удалён диалог выдачи разрешения на установку.
ApplicationLoader.openApkInstall всегда возвращает false. Оба файловых обработчика
AndroidUtilities прекращают открытие APK по MIME или расширению .apk до передачи
плагинам и Intent.ACTION_VIEW. Обычные документы и медиа остаются доступны.
Это изменение не отключает выполнение произвольного кода системой плагинов.

Обновление собственного клиента остаётся ручным: скачать APK из GitHub Actions и
открыть его файловым менеджером/браузером Android. Постоянный applicationId и ключ
подписи не изменены.

## Проверки

`python3 tests/test_no_app_updater.py -v`:

- отсутствие активного разрешения на установку APK;
- отсутствие удалённых классов и известных вызовов установщика/проверки обновлений;
- выполнение настоящего Java-метода распознавания APK в 10 сценариях с APK,
  обычными документами, фото, ZIP и пустыми параметрами.

Также проверены синтаксис изменённых Java/Kotlin, Android XML, workflow shell/Python
и git diff --check. По просьбе пользователя Gradle и GitHub Actions не запускались.
Компиляция всего приложения, merged manifest и поведение на телефоне пока не проверены.
При следующей сборке workflow проверит отсутствие REQUEST_INSTALL_PACKAGES в готовом APK.
Перед использованием проверить вход, чат, открытие обычных файлов, старую ссылку
`tg://update`, отсутствие обновлятора в настройках и установку следующей версии поверх.
